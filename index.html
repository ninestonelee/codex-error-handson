한 줄 요약

까만창 에러는 종류가 여섯 가지뿐이고, 어느 종류인지는 에러 메시지의 "마지막 구체적인 한 줄"이 알려줍니다.

앱이 보여주는 "Codex CLI 실행환경, 로그인 상태, 모델 설정을 확인해 주세요"는 모든 실패에 똑같이 붙는 공통 안내문이에요. 이 문장만 보고 "로그인 문제구나" 하고 재로그인부터 하면 열에 아홉은 헛수고입니다. 그 문장 아래나 위에 있는 구체적인 영어·숫자 한 줄이 진짜 원인이에요.

0. 에러가 나면 제일 먼저 — 3분 (유형 상관없이 공통)

비유로 말하면, 앱은 사장님이고 코덱스(까만창)는 조사·집필을 맡은 직원이에요. 직원이 일을 못 하는 이유는 "출근을 못 함(실행 파일)", "사원증이 없음(인증)", "그 업무 권한이 없음(모델)", "오늘 할당량을 다 씀(사용량)", "보고서를 안 냄(결과 파일)", "보고서 내용이 부실함(글 품질)" 여섯 가지 중 하나예요. 사원증 문제인데 출근길을 고치면 소용없죠. 그래서 유형부터 가려야 합니다.

1. 내 에러는 어느 유형? — 문구로 찾기

화면이나 로그에 보이는 말을 아래에서 찾으세요. 왼쪽 문구가 보이면 오른쪽 장으로 바로 가면 됩니다.

화면·로그에 보이는 말 유형 갈 곳
실행 파일이 없습니다 / 찾을 수 없습니다 / ENOENT 출근 못 함 (실행 파일) 3-A
3221225794 / 0xC0000142 / -1073741502 출근 못 함 (DLL) 3-B
model is not supported … ChatGPT account 권한 없음 (모델) 3-C
Selected model is at capacity 창구 혼잡 (모델) 3-D
usage limit / usage_limit_reached / 한도 할당량 소진 (사용량) 3-E
로그인 필요 / 인증 실패 사원증 (인증) 3-F
종료 코드 1 숫자만으론 모름 3-G
result file was not created / JSON 오류 보고서 미제출 (결과 파일) 3-H
N분 제한 시간 / N분 동안 출력 없음 시간 초과 3-I

이미지 누락 / 주간 잔량 - 이미지·표시 문제 3-K
근거 부족 / Main Review 미통과 보고서 부실 (글 품질) 3-L

가장 흔한 것은 3-C 모델 미지원이에요. 보존된 실패 기록 16건 중 13건이 이거였어요. 실행 파일 없음은 1건, 혼잡 1건, DLL 1건이었습니다. (이 비율은 수집된 기록 기준이고, 모든 수강생 PC가 똑같다는 뜻은 아닙니다)

2. 공통 도구 — PowerShell로 3가지 확인하기 (5분)

유형 A·B·F·G에서 공통으로 쓰는 확인법이에요. 한 번 익혀 두면 됩니다.

2-1. PowerShell 열기

2-2. 윈도우가 아는 코덱스 위치 보기

Get-Command codex -All | Select-Object CommandType, Source

주의: 여기서 찾은 코덱스와 앱이 실제로 쓰는 코덱스는 다를 수 있어요. 데스크톱 앱과 따로 설치한 CLI의 버전이 다를 수 있습니다. 앱 에러에 표시된 경로가 있으면 그게 기준입니다.

2-3. "그 파일"이 켜지는지 확인

실제경로 자리에 앱이 쓰는 codex.exe의 전체 경로를 넣습니다. 맨 앞 &와 따옴표는 그대로 둡니다.

& 'C:\실제경로\codex.exe' --version

2-4. 로그인 상태 확인

& 'C:\실제경로\codex.exe' login status

경로를 모르면 강사에게 물어보세요. 다른 설치본에서 버전이 잘 나왔다고 앱 문제가 풀린 건 아닙니다.

3. 유형별 핸즈온

각 유형은 증상 → 쉬운 뜻 → 내가 할 것 → 됐는지 확인 → 하지 말 것 → 강사에게 보낼 것 순서예요.

3-A. "Codex 실행 파일이 없습니다"

증상: 실행 파일이 없습니다 / 찾을 수 없습니다 / ENOENT

쉬운 뜻: 앱이 적어 둔 주소에 가 봤더니 코덱스 파일이 없어요. 데스크톱 앱 설치 위치가 바뀌었거나, 예전 경로가 설정에 그대로 남아 있을 때 생깁니다. 지금 소스는 %LOCALAPPDATA%\OpenAI\Codex\bin을 찾지만, 실제 설치 사례는 %LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe였어요. 두 주소가 다르죠.

내가 할 것:

됐는지 확인 앱이 고른 그 파일에서 버전이 나오고, 앱 사전 점검에서 실행 파일 오류가 사라져야 합니다.
하지 말 것 네이버 비밀번호 바꾸기, 코덱스 재로그인. 이 유형과 무관합니다.
강사에게 보낼 것 runtime 경로, 2-2에서 나온 경로 목록, --version 결과.

3-B. "종료 코드 3221225794" / "0xC0000142"

증상: 3221225794, 0xC0000142, -1073741502 중 하나. 셋은 같은 값을 다르게 표시한 것입니다.

쉬운 뜻: 윈도우가 프로그램에 필요한 부품 파일(DLL)을 초기화하지 못했어요. 어떤 부품인지, 설치 손상인지, 백신 영향인지는 아직 모릅니다. 옆에 모델 이름이 찍혀 있어도 모델 문제가 아니에요.

내가 할 것:

됐는지 확인 같은 파일에서 --version과 login status가 모두 통과.
하지 말 것 인터넷에서 DLL 파일 받아 넣기, 백신 통째로 끄기. 코드 하나로 "재배포 패키지가 없다"고 단정하기.
강사에게 보낼 것 이벤트 뷰어의 세 항목(사용자 경로·계정명은 가리고), 재시작 후 결과.

3-C. "이 모델은 ChatGPT 계정에서 지원되지 않습니다" ← 가장 흔함

증상: model is not supported … ChatGPT account

쉬운 뜻: 로그인은 돼 있어요. 그런데 앱이 고른 AI 모델을 내 계정으로는 쓸 수 없다는 응답이에요. 사원증은 있는데 그 업무 권한이 없는 상태. 과거 기록엔 gpt-6-sol, gpt-6.1-sol, gpt-6-luna가 거절된 적이 있는데, 그건 그 시점·그 계정 이야기이고 지금 모든 계정이 그렇다는 뜻은 아닙니다.

내가 할 것:

됐는지 확인 모델 미지원 문구가 사라지고 "생성" 단계가 진행돼야 합니다. 예전에 5.6 Sol로 성공한 기록이 있어도 지금 내 계정의 성공을 보장하진 않아요. 앱은 미지원 모델을 만나도 다른 모델로 자동 변경하지 않습니다.
하지 말 것 재로그인, 재설치. 둘 다 이 유형과 무관.
강사에게 보낼 것 거절된 모델 이름, 내가 바꿔 본 모델과 결과.

3-D. "Selected model is at capacity" — 창구 혼잡

증상: Selected model is at capacity

쉬운 뜻: 서버가 "그 모델은 지금 줄이 너무 길다"고 답한 거예요. 파일 없음도, 모델 미지원도, 내 사용량 소진도 아닙니다.

내가 할 것:

됐는지 확인 같은 혼잡 문구가 사라지고 생성이 진행.

3-E. "사용량 한도에 도달했습니다"

증상: usage limit / usage_limit_reached / 한도

쉬운 뜻: 오늘(또는 이번 주) 쓸 수 있는 양을 다 썼다는 신호예요. 할당량 문제라서 앱 재설치나 네이버 재로그인으로는 절대 초기화되지 않습니다.

내가 할 것:

주의 두 가지:

  • 429라는 숫자만 있으면 "요청 빈도 제한" 같은 다른 제한일 수 있어요. 상세 응답을 같이 보세요.
  • 앱의 주간 잔량이 -로 보이는 건 조회 실패일 수 있어요. 잔량 0의 증거가 아닙니다.
하지 말 것 초기화 시각을 못 찾았는데 "몇 시간 기다리면 되겠지" 하고 단정하기. 계정의 사용량 안내 페이지를 확인하세요.

3-F. 진짜 로그인(인증) 오류

먼저 구분: 공통 안내문에 "로그인"이 들어 있다는 이유만으로 재로그인하지 않습니다. 2-3 버전 확인이 정상이고, 2-4 login status에서 로그인 안 됨이 확인됐을 때만 진행해요.

내가 할 것:

& 'C:\실제경로\codex.exe' login
됐는지 확인 login status 통과 + 실제 생성 요청에서 인증 오류가 없어야 합니다. 상태 검사는 통과해도 실제 요청에서 걸릴 수 있으니 마지막 응답까지 보세요.
하지 말 것 auth.json 파일, 일회용 로그인 코드, 토큰을 단톡방·공유 폴더에 올리기. 절대 안 됩니다.
강사에게 보낼 것 계속 실패하면 "앱과 PowerShell이 같은 윈도우 사용자인지"를 강사가 확인해야 해요. 로그인 시도 결과만 보내 주세요.

3-G. "종료 코드 1" 또는 연결·서버 오류

증상: 종료 코드 1, 또는 DNS·TLS·연결 끊김·서버 응답 오류

쉬운 뜻: 1은 "정상 종료 못 했다"는 가장 일반적인 결과예요. 기록에서 모델 미지원도, 혼잡도 전부 코드 1로 끝났어요. 숫자만으로는 원인을 고를 수 없습니다. 그 위의 마지막 구체적인 줄을 봐야 해요.

내가 할 것:

하지 말 것 인증서 검증 끄기, 보안 정책 우회. 원인 문구가 없는데 "재설치하면 되겠지", "모델 바꾸면 되겠지" 단정하기.
됐는지 확인 구체적인 오류 응답이 사라져야 합니다. 원인 문구가 아예 없으면 "로그 부족"으로 기록하고 강사에게.

3-H. "research-title-result.json이 생성되지 않았습니다" / JSON 오류

증상과 뜻: JSON은 AI 직원이 앱에 내는 보고서 양식이에요. 양식이 다섯 단계(조사·제목 → 작성 지침 → 본문 → 검수 → 이미지)마다 다음 단계로 넘어갑니다.

문구 쉬운 뜻
result file was not created 보고서 자체가 없음
Expected double-quoted property name 양식 문법(큰따옴표 등) 틀림
Bad control character in string literal 허용 안 되는 문자가 섞임
Unexpected token 예상 밖 문자가 들어감
결과 계약 검증 실패 읽히긴 하는데 필수 항목·형식이 앱 규칙과 안 맞음

코덱스가 종료 코드 0(정상)으로 끝나도 보고서가 없거나 양식이 틀릴 수 있어요.

내가 할 것:

하지 말 것 빈 JSON 파일 만들기, status를 손으로 "성공"으로 바꾸기. 뒤 단계 검수에 잘못된 자료가 들어갑니다. 결과 파일 원문엔 글 본문·개인정보가 있을 수 있으니 통째로 공유 폴더에 올리지 않기.
강사에게 보낼 것 실패한 단계 이름, 직전 오류 문구, 최종 상태. 강사가 파일 존재·문법·필수 항목·작업 폴더 쓰기 권한·디스크 공간을 확인합니다.

3-I. "제한 시간 안에 끝나지 않음" / "출력이 없어 중단"

쉬운 뜻: 기본값은 코덱스 한 번 실행에 전체 60분, 연속 무출력 15분이에요(설정에 따라 다를 수 있음). "무출력"은 앱이 진행 신호를 못 받았다는 뜻이지 AI가 멈췄다는 증거는 아닙니다. 이 경우 앱은 코덱스를 종료하고 실패 처리해요.

내가 할 것:

하지 말 것 시간 제한을 무조건 늘리기. 멈춘 작업을 더 오래 기다리게 될 뿐이에요. 원인 확인 뒤에 범위 조정이나 제한 변경.

3-J. 옵션 미지원 / image_generation 없음 / xhigh 미지원

쉬운 뜻: 앱이 요구하는 기능과 내 PC의 코덱스 CLI 버전이 안 맞아요. npm 래퍼·node.exe를 못 찾는다는 문구도 같은 계열입니다.

내가 할 것:

하지 말 것 "지원하지 않는 래퍼"라고 나왔을 때 보안 제한을 풀어 우회하기. 앱은 표준 npm 래퍼 또는 실제 .exe만 받고 임의 .cmd·.bat는 거부해요.

3-K. 이미지가 없거나 사용량 표시가 안 나옴

쉬운 뜻: 세 가지를 구분해야 해요. ① 이미지 생성 기능 자체가 없음(3-J) ② 이미지 결과 파일 누락 ③ 이 글과 이미지의 연결 검증 실패. 앱은 다른 글의 이미지를 추측해서 끼워 넣지 않도록 검증합니다. 이미지 일부 실패는 경고와 함께 본문만 진행될 수 있어요. 이미지 실패가 글 전체 실패는 아닙니다.

내가 할 것:

3-L. 근거 부족 / Main Review 미통과 / 기타 차단

쉬운 뜻: 이건 고장이 아니라 앱이 글의 신뢰성을 지키려고 일부러 멈춘 것이에요. 출처가 약하거나 검수를 못 넘긴 거죠.

내가 할 것:

하지 말 것 검수 규칙 끄기, CLI 재설치. 재설치로 풀리는 문제가 아니에요.

4. 설정 파일에서 코덱스 경로 바꾸기 (3-A 확인된 경우에만)

이 절차는 3-A에서 "실행 파일 경로 문제"가 확인된 경우에만 씁니다. 탐색기 주소창에 %APPDATA% 같은 환경변수를 넣으면 그 폴더로 이동해요.

"codexCmdPath": "C:/Users/사용자이름/AppData/Local/Programs/OpenAI/Codex/bin/codex.exe"

codexCmdPath 항목이 아예 없거나 runtime 폴더를 못 찾겠으면 파일을 새로 만들지 마세요. 설치본과 개발본을 같이 쓰는 분은 각각 다른 설정 파일을 읽을 수 있어요.

5. 다 고쳤는지 확인하는 4단계

순서대로 통과해야 "해결"이에요. 앞 단계 통과가 뒤 단계를 보장하지 않습니다.

순서 확인 통과 기준 이걸로는 아직 모르는 것
1 같은 파일 --version 버전 출력 인증·모델 지원
2 같은 파일 login status 로그인 확인 실제 모델 요청 성공
3 앱 사전 점검 경로·버전·인증·옵션·이미지 기능 통과 생성·검수·게시 성공
4 발행 끈 수동 생성 결과 파일·검수 통과, 미리보기 확인 실제 네이버 게시

4단계 할 때 꼭 이렇게:

6. 강사에게 물어볼 때 — 이 양식으로

이걸 채워서 보내면 "재설치해 보세요" 같은 막연한 답 대신 바로 원인으로 갑니다. 화면 캡처는 글 본문·이메일·PC 사용자 이름을 가린 뒤 필요한 부분만.

부록 A. 용어 한 줄 사전

  • 코덱스 CLI(까만창): 앱이 글 조사·집필을 시키는 별도 프로그램. 키보드 명령으로 쓰는 프로그램이라 까만 창으로 보여요.
  • PATH: 윈도우가 프로그램을 찾아보는 폴더 목록. 여기 없어도 프로그램은 있을 수 있어요.
  • runtime 폴더: 앱이 설정·이력을 저장하는 폴더. 앱 상단에 표시돼요.
  • codexCmdPath: 설정 파일에서 "코덱스가 어디 있는지" 적어 둔 항목.
  • JSON: AI와 앱이 주고받는 보고서 양식.
  • 모델: 글을 쓰는 AI의 종류. 계정마다 쓸 수 있는 모델이 달라요.
  • 추론 강도(high/xhigh): 모델이 얼마나 깊게 생각할지. 모델 이름이 아니에요.
  • 종료 코드: 프로그램이 끝나며 남기는 숫자. 0은 정상, 1은 "뭔가 실패"이고 이유는 다른 줄에 있어요.

부록 B. 세 가지 로그인은 서로 다른 것

로그인 무엇에 쓰나 이걸로 풀리는 문제
앱 Google 이용권 로그인 앱 사용 권한 이용권 만료
코덱스 로그인 AI 직원 사원증 3-F 인증 오류만
네이버 로그인 블로그 발행 네이버 세션 만료만

코덱스 실행 파일 오류(3-A)를 네이버 비밀번호를 바꿔서 풀 수는 없어요. 어느 로그인인지부터 보세요.

부록 C. 이 문서가 보장하지 않는 것 (솔직하게)

  • 이 문서는 2026-09-06 ~ 10-03 사이에 수집된 오류 기록 28건과 앱 소스를 대조해 쓴 확인 절차예요. 모든 수강생 PC에서 복구가 완료됐다는 뜻은 아닙니다.
  • DLL 오류(3-B)의 구체적인 원인 모듈, 서버 쪽 실패 44건의 원인별 수, 각자 계정의 현재 모델 지원 여부는 아직 확인되지 않았어요.
  • 앱 자체의 개선(새 설치 위치 자동 탐색, 오류 분류 세분화, 반복 실패 억제 등)은 예정 상태라, 이 문서가 생겼다고 지금 설치된 앱의 동작이 바뀌진 않습니다.
